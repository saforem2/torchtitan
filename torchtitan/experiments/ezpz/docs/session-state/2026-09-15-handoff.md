## Where the MoE port stands

Only **`aurora_sycl`** is portable as a drop-in: its
`torchtitan_exact_experts(w1,w2,w3,x,expert_rows)` matches our backend slot exactly,
kernels JIT-compile via `torch.utils.cpp_extension.load`, and Aurora has the oneMKL
headers + `libmkl_sycl_blas.so.5` it probes for at
`/opt/aurora/26.26.0/oneapi/mkl/2025.3`.

`scattermoe` and `aurora_full_*` need `top_scores` / `selected_experts_indices`, which
our `GroupedExperts.forward(x_RD, num_tokens_per_expert_E)` never receives -- upstream
moved dispatch into the token dispatcher, sww's branch predates that. `aurora_full_*`
additionally requires an EP mesh. Those are a restructuring, not a port.

Backends are selected by **model flavor** (`10B_2B_50K_sdpa_aurora_sycl`,
`10B_2B_sdpa_scattermoe`), not a config field -- which is exactly what the 7 failing
tests in `tests/unit_tests/test_moe_expert_backends.py` reference.

Worth weighing: **none of sww's 12+ real run configs select any of these backends**
(they use `enable_data_parallel_replicate_module: true` + `expert_parallel_degree: 12`),
and `scattermoe` has no dependency pin anywhere in his branch.
