## 1. MoE at TP>1

Four days, twelve dead hypotheses, one wrong fix.

Everything static matched between `agpt` and `moe`: config population, layout
axes, arg names, the parallelize branch, the `local_map` install. Measured, not
assumed -- job `8789506` shows both models' SDPA wrapped on the same mesh
`('tp',)(2,)`, and both declare `['cp','dp','tp']` on every in/out/grad entry.
That is why comparing configs kept failing. The difference was in the code.

The first fix was wrong. Copying `agpt`'s
`out_TNH.view(out_TNH.shape[0], -1)` verbatim reads `moe`'s **batch** axis,
because `agpt`'s SDPA returns 3D and `moe`'s returned 4D:

```
RuntimeError: mat1 and mat2 shapes cannot be multiplied (1x1048576 and 2048x256)
```

That broke TP=1, which had always worked. The TP=1 regression arm in
`lm-probe.sh` is the only reason it did not ship. `agpt`'s own comment warns
about it -- "reads the wrong stride off a 4D tensor" -- and the `moe` port
(`e4517ae09`) had copied the input half and dropped the output half.

Verified, job `8787243`, 4 ranks, TP=2, 5 steps, nocompile:

| arm | step 1 -> 5 |
|---|---|
| `agpt` | 10.88838 -> 10.43820 |
| `moe` tp=1 | 12.93609 -> 11.32376 |
| `moe` tp=2 | 12.94930 -> 11.49335 |

The two `moe` arms agree to 0.011 at step 1 and track within 0.17 over five
steps, and TP=2 holds less memory per rank than TP=1 (1.93 vs 2.78 GiB).

TP=2 only, 4 ranks, 5 steps, nocompile. No TP=4, no compiled `moe`, no scale
run. The TP=1/TP=2 agreement is close but not bitwise and there is no numeric
equivalence test.

Five blockers came out before `moe` reached attention at all: missing
`in_dst_shardings` entries, a `dense_activation_placement()` keyword,
`Shard(n)` -> `spmd.S(n)` in the param layout, the #4121 fold, and the flat-MLA
port. Two of the six MLA changes -- `k_pe.unsqueeze(1)` and
`expand(-1, k_nope.size(1), -1)` -- only bite at tp>1, and no single-rank test
reaches them.

## 4. Failover

**`8773440` lost 7 of its 12 hours to a regex.** ezpz 0.21's progress detector
matched `\bstep=\d+`; torchtitan prints `step: 21800`. Measured on that job's
own logs, seats that had trained 201 / 504 / 782 steps all scored no-progress
under 0.21 and all three score correctly under 0.27.3. `t3` was killed right
after a checkpoint. Fixed upstream, pinned by a CPU-only contract test.

**And ~5 more hours to seats that exited and left their slice idle.** Every
seat was gone by 04:27; PBS did not kill the shell until 09:29.
`supervise_trainer()` now relaunches, with four guards: a deadline read from
`qstat`, a quick-death cap, `rc=0`, and an explicit off switch.

**Polaris failover was blind.** Zero patterns registered for the machine, so
every rotation swapped a healthy node and left the sick one in -- no error,
because an empty pattern set and a clean log both return `[]`. Then
`get_machine()` returned a login FQDN against bare registry keys, so the
patterns that existed were unreachable. Cost: job `7550301` ~1h of 130 nodes
with zero steps; `7560196` 3h03m, `Exit_status=124`.

Two Polaris nodes carry a stuck GPU from another user's job that PBS cannot
see -- `pbsnodes x3111c0s37b1n0 | grep comment` names it in one line, ngpus
still reads 4, and rotation cannot win. Drain ticket drafted, not sent.

Three green gates in this range were testing the policy and not the binding.
The grad-norm guard is the canonical case: validated by replaying finished
logs, it read a name local to `train_step`, `NameError`'d on step 1, and PBS
still reported `Exit_status=0` with the done-marker written. All three now
assert on the runtime path.

### SophiaG

Disqualified at 4/4. Onsets 1048, 1176, 1071, ~1550. The fresh independent
replicate with the seed pinned diverged too, and escalated 0.20 -> 4.95 ->
36.14 -> 98.98 -> 731.80 across four steps under a nearly flat loss (2.952 ->
3.641). Read `grad_norm`, never loss -- the loss dips look like recovery.

The guard's first live catch: replicate 3 stopped at `grad_norm` 53.49, 133x
the trailing median, `rc=0` after 55 minutes instead of ~8h.

Full-chain excursion census, steps above 2.0:

| arm | excursions | max |
|---|---|---|
| adamw | 54 / 1,984 (2.7%) | 14.6 |
| mano | 128 / 1,983 (6.5%) | 30.0 |
| sophiag | 573 / 1,524 (37.6%) | 100,611 |
| sophiag rerun | 380 / 644 (59.0%) | 204,017 |

The earlier version of that table read zero for the healthy arms. A chained arm
is N jobs with N logs and `ls -1dt | head -1` reads only the newest. Fixing it
inverted the published framing from bimodal to escalation.

The metastability claim was retracted twice inside this range before binning
settled it: "persists 300+ steps" -> "does not leave that regime" (written off
~400 post-onset steps that all sat inside the bad window) -> one diverged arm
recovering fully ~600 steps after a 100,611 spike while its twin from the same
checkpoint never did. Decline is not monotone. Bin into windows and compare a
sequence.

The practical conclusion never moved: an optimizer that can re-enter a
27,000-grad-norm state after a hundred healthy-looking steps is unusable in
production.

## 6. Dashboard and eval

**Eval scores had been resolving to `{}` for every chain since the feature
landed.** Two independent bugs: `_eval_scores` took the checkpoint directory
name (`agpt-2b-sophiag-olmo-mix-1124-n512-gbs12288`) while eval sweeps write to
a short alias (`agpt-2b-v2-512n`), schemes that have never matched. The
original tests passed because they ran against a synthetic tree built to the
shape the code expected.

**`refresh_all.sh` had been auto-committing two eval charts with their data
deleted.** Measured by distinct-color count, which is the tell for this class:
2b went 5 series -> 2, 20b went 6 -> 3. Both plotters now refuse to overwrite a
good figure with an empty one -- though the guard only fires when *every*
disk-backed series is empty, so a partial-data run still writes a degraded
figure and exits 0.

**The web dash survives a width change** and shows every metric at once, with
per-cell maximize. Verified in a browser against the live 780KB payload: at
1600 -> 1100 -> body padded 320px, every canvas matches its host, 0 overflow.
Eval panels now fit their data instead of `[0,1]` -- `mmlu` lives in a 5pp
window and was a flat line before. That reverses a deliberate decision from the
day before, which had argued a probability belongs on `[0,1]`; the counter is
that a 5pp signal on a `[0,1]` axis is not a chart.

The offline cache now actually gets written. The monitor that "verified" the
first attempt only checked that the dash served 200, and reported that as
healthy.
