## 3. Production-batch LR-finder campaign (2B / 20B / 80B)

The big analysis thread of the window: re-run the LR finder **at the
production batch** across all three sizes and settle whether the 80B NaN
"cliff" is a universal scaling law or large-model-specific.

- **80B @ GBS=6144** (the 2026-06-27 sweep, per optimizer): **AdamW is on a
  NaN cliff** -- usable LR ceiling ~7e-7, and the production default LR=1e-6
  sits *past* the last stable point (NaN onset 1.36e-6). **mano** is the
  best-behaved (clean broad U-min, ~1.6e-5, suggest ~3e-6); **sophiag** is
  NOT broken at this batch (real U-min ~2.5e-6, lowest loss) -- correcting the
  old "SophiaG broken at 80B" claim, which was batch-specific (GBS=192). Only
  **muon** stays broken (bf16 overflow, dim=9216). The LR-ceiling-vs-GBS trend
  shows AdamW's ceiling falling ~20x with batch then cliffing.
  [`lr-finder/agpt/80b`](../experiments/lr-finder/agpt/80b/README.md).
- **2B never cliffs.** The same 16N/dp=192 trend at 2B across GBS 192..24576
  (128x batch): every optimizer a clean U-min, 0 NaN everywhere; usable LR
  flat ~1e-2. A 100-step production-batch ladder (jobs 12469854-868, 15/15,
  0 NaN) confirmed it at the classic finder length -- no batch-scaling trend.
  [`lr-finder/agpt/2b`](../experiments/lr-finder/agpt/2b/README.md).
- **20B never cliffs either** (jobs 12469786-815, GBS 192..12288, 0 NaN all
  cells). So the cliff is **not** a smooth function of size that 20B sits
  midway on -- 20B is firmly on the clean side of a threshold only 80B
  (dim=9216 bf16) crosses. [`lr-finder/agpt/20b`](../experiments/lr-finder/agpt/20b/README.md).
- **Conclusion:** the batch-dependent usable-LR collapse is large-model-
  specific, likely the same dim=9216 bf16 fragility that breaks muon/sophiag.
  A small-batch finder cannot calibrate a large-model production LR; small
  models are themselves forgiving of large batches.
- **Charts + docs:** house-styled (ambivalent + Iosevka), per-GBS loss-vs-LR
  families, a cross-model grid at GBS=6144, and a combined all-optimizer x
  all-batch plot (hue=optimizer canonical colors, batch = shade+width+opacity).
  Fixed a `load_curve` bug that truncated 30-step sweeps' x-axis to 1e-3.

## 4. 80B convergence run -- all optimizers NaN past warmup (Sunspot)

The follow-up the finder called for: run each optimizer at its finder LR as a
**constant** LR for more steps than the 15-step finder (jobs 12469910/911/912,
GBS=6144, 64N).

- **All three diverged**: each descends a few steps then grad_norm explodes ->
  loss NaN. **mano @ 3e-6 dies first (step 5)**, AdamW @ 5e-7 (step 9),
  sophiag @ 1e-6 (step 12). grad_norm is the leading indicator (blows up one
  step before loss).
- The finder's early-step ranking does **not** predict sustained stability; a
  failure shared across three very different optimizers points to a
  corner-level instability (bf16 at dim=9216), not optimizer tuning. No finder
  LR is production-safe as a constant LR here -- needs a long warmup (>=200
  steps) + grad clipping, possibly an fp32 grad path.
- Report:
  [`2026-06-30-80b-convergence-gbs6144.md`](../experiments/agpt/sunspot/2026-06-30-80b-convergence-gbs6144.md).

## 5. 80B post-maintenance production launch (Aurora)

After the PM window, launched the 80B SophiaG/constant-LR production brackets
(512N/1024N/2048N).

- **2048N head (8574387) SIGSEGV'd in `set_determinism`** at **24,864 ranks**
  (seed broadcast in `distributed/utils.py`; CCL/PMI KVS "Connection reset by
  peer"). Config echo was correct (GBS=6138, TP=4, LBS=1, compile OFF,
  SophiaG, constant-LR) and the venv broadcast finished first -- this is the
  documented init-crash class (2B/20B at 1024N/12,288 ranks), now confirmed
  for 80B at 2048N.
- **512N (dp=1530) runs; 1024N (dp=3066) is the missing measurement** that
  brackets the init-crash ceiling. If 1024N survives init the ceiling is
  ~2048N-specific; if not, 512N is the practical 80B max on this stack.
- **Op lessons recorded:** (a) after a reservation tears down, a large job can
  eat several exec-server rejects before nodes stabilize -- *wait, don't
  requeue* (requeue forfeits priority) as long as peer large jobs are placing;
  (b) auto-retry misclassified the rank SIGSEGV (rc=143/SIGTERM) as a walltime
  stop and did not consume retries -- a real classifier gap (moot for a
  deterministic crash, but a swappable bad-node SIGSEGV would also be missed).
  `qhold`'d the 2048N continuation (afterany fires on failure too). Corrected
  the dashboard/80b rollups from "launching" to the crash outcome.
  [`80b/README`](../../live/chains/agpt/80b/README.md).

## 6. Multi-node vLLM GRPO -- cross-node generation works, multi-trainer-node walled

Extended the 1-node TRL vllm-serve GRPO (from the prior window) toward true
multi-node, with a deep debugging arc.

- **Cross-node generation works (2N).** Server on the head node, trainer on
  another node reaching it over the real hostname; 10/10 GRPO steps, real
  accuracy reward, active weight-sync (job 12469976). Production script
  [`aurora2b_sft_arithmetic_vllm_xnode.sh`](../../rl/scripts/grpo/aurora2b_sft_arithmetic_vllm_xnode.sh).
- **Multi-*trainer*-node (2+ trainer nodes) is blocked.** Two real fixes landed
  along the way (both correct, both prerequisites): FSDP2 **AVG->SUM** via the
  public `set_force_sum_reduction_for_comms` (oneCCL scheduler path has no AVG
  kernel), and a togglable `--no-oneccl-tcp-kvs` so the trainer stays on
  pmix/CXI. But the run still hangs at generation.
- **Root-cause investigation (multi-agent fan-out + faulthandler):** four
  hypotheses ruled out by fast minimal repros (object collective, transport,
  FSDP-interleave, lazy new-comm all work in isolation on clean CXI). A rank-0
  C++ stack localizes the hang to
  `ProcessGroupXCCL::broadcast -> initXCCLComm -> atl_mpi::allgatherv` (TRL's
  `broadcast_object_list`). Leading remaining hypothesis: **rank desync** in
  the real generation path; all-rank stacks not yet captured (faulthandler-to-
  file failed under the GIL-held C++ hang). Next tactic documented: `py-spy
  dump`. [`grpo-on-xpu-status.md`](../../live/chains/rl/README.md) was also
  restructured status-first with the history collapsed.
- The **completed 8N GRPO run's reward was backfilled** (1.26 last-10-mean,
  acc 0.76) into [`production/grpo/README`](../../live/chains/rl/grpo/README.md).
